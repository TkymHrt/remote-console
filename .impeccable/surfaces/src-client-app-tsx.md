# Remote Console / main surface

Mode: Operate

Audience: 外出先から一台の自宅PCへ接続する本人。
Task: 応答状態を読み、必要なら起動を依頼し、RDPの準備ができたら接続する。
Content: PC名、現在状態と短い説明、一つの次の操作、最終確認。接続方式と最終起動時刻は開閉できる補助情報。
Constraints: 既存APIの4状態、起動のクールダウン、通信失敗、サーバー固定の接続先、Cloudflare Accessを維持する。

## Direction contract

THESIS: 一台への起動依頼と接続確認を、一枚の操作票として扱う。状態→一つの操作→補助情報の順だけを残す。

OWN-WORLD: 暖かい紙色の背景と明るい一枚のシート、濃い文字、細い区切り線。青は実行できる主操作だけに使い、状態は小さな色点と日本語で伝える。紙のテクスチャや装飾的な印影は使わない。

STORY: PC名の下に今の状態が大きく示され、すぐ下の操作で起動・待機・接続・再確認へ進む。確認時刻は上端にあり、起動履歴と接続方式はシートの外の詳細開閉から読める。

FIRST VIEWPORT: 小さなヘッダーの下、PC名と一枚の操作票を中央に置く。シート内は上から確認情報、大きな状態、操作と短い補足。スマートフォンでは操作と補足を縦に並べ、主操作を最初の画面内に収める。起動待ちの点だけが静かに呼吸し、状態テキストは短く切り替わる。

FORM: 自宅へ起動依頼を送って応答を待つ体験から導いた「Dispatch Sheet」。方向シード 82cfdfc2。デザイン方向は依頼者が委ねたため、操作の明快さを優先して選択した。

FINISH: デスクトップとスマートフォンの実画面、状態遷移、クールダウン、通信失敗を確認し、DESIGN.mdとデザインサイドカーへ実装した規則を反映する。
